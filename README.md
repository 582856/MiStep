# 小米步数管理 · HyperOS 4

基于 [LinYuLuo/MiStep](https://github.com/LinYuLuo/MiStep) 继续维护，原开发者 **XyLin**，新接手者 **枫彡**。沿用 Apache-2.0 许可证，原作者说明保留在下方。

当前版本：`1.06-os4`；应用包名：`cn.zephyr.mistep`。

[下载小米版安装包](https://github.com/582856/MiStep/releases/tag/v1.06-os4)

## 本分支改动

- 适配 HyperOS 4 的运动权限和 ROOT 读取路径，读取失败时停止修改，不按 0 步处理。
- 指定步数重复执行不累加；减少步数不再插入负记录，修改后回读验证。
- 计入模式 2/3/4 的记录；支持处理旧负记录，修改前备份受影响记录到应用私有目录。
- ROOT 操作移出主线程，修正自动任务去重、日期判断和通知权限处理。
- 底部导航栏透明，移除蓝色背景和系统对比蒙层。
- 保留共享的一加兼容代码；本次发布的名称与安装包仍为小米版，不含天猫快捷入口。

## 使用

授予“身体活动/运动”权限，并在 ROOT 管理器中授权本应用。长按“修改步数”可切换 ROOT / 核心破解模式；核心破解模式依赖系统额外授权，并非免 ROOT 通用方案。

仅修改本地系统计步记录，不保证小米运动健康、微信等应用的缓存刷新或第三方平台同步。定时功能依赖系统后台调度，自启动和省电限制可能导致延迟。

## 构建

使用 JDK 17 或以上、Android SDK 36，配置本机 SDK 路径后运行：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
.\gradlew.bat :app:assembleRelease
```

Debug 包使用本机调试签名；Release 构建产物未签名，需自行签名。仓库不包含签名密钥、设备日志或个人计步快照。自行签名的包不能直接覆盖不同签名的已安装版本。

Release 附件沿用此前交付的已签名小米 `1.06-os4` 安装包；本仓库源码经过发布整理，包含后续共享兼容代码，不承诺与该附件逐字节一致。

`app/src/test` 为纯逻辑测试。`app/src/androidTest` 的真机测试会临时改写计步记录，不会在普通构建中运行，请勿在个人数据设备上直接执行。

## 原作者说明

### 小米步数管理（重制）
　　时隔一年，小米步数管理又完善了一点点。第一代在完成1.35的时候就被我放弃了，原因有很多，例如ROOT模式使用的SQLite3在高版本并不是特别好、其次每天手动打开软件让我很烦躁、还有6月份的时候换三颗星了......

　　所以这一次为大家带来了可能、大概、也许、应该是最终版的小米步数管理，它拥有：增加和指定两种修改步数类型、第一次打开和0点定时（需要手动为APP启用自启动权限）两种自动修改方式、核心破解和ROOT两种修改模式。其中ROOT模式采用GitHub用户“nkh0472”提供的content命令进行修改，完美解决了第一代因使用SQLite3命令导致的无法修改步数和电量与性能屡次停止运行问题，非常感谢这位用户提供的思路。

　　在此对我放弃小米步数管理项目期间通过邮件反馈问题的用户表示歉意，因为开发者的懒惰导致了你们的问题无法解决......

　　负一屏或健康APP显示的步数无法减少不是BUG，是官方修改了统计方式。当初能够减少步数可以说是官方BUG，现已修复。

　　禁用/卸载“电量与性能”或“Joyose”APP可能会导致系统无法记录步数，因此APP也无法修改步数。
